# Дневник — MVP школьного домашнего задания

Первый модуль будущей единой информационной базы. Приложение помогает быстро
записать домашку текстом, разложить её по предметам и датам, вести расписание
на шесть учебных дней и выгрузить всё в JSON.

Дизайн — минималистичный, в стиле референсов `Physics.html` и
`Литературичка.html`: светлый фон `#f4f4f5`, белые карточки, тёмная тема
`#09090b` / `#18181b`, скругления 24–32 px, шрифт Nunito (вшит в проект),
монохромный акцент и плавающая капсула в нижней навигации.

---

## Что умеет

- **New** — большое поле, чипсы предметов, Т9-подсказки по началу слова
  (`общ…` → «Обществознание»), счётчик распознанных задач.
- **Мульти-вброс** — одна строка делится на несколько задач по хэштегам.
- **Умный парсер** — убирает хэштеги из описания, понимает алиасы, считает
  дедлайн и перешагивает выходные (пятница/суббота → воскресенье 20:00).
- **Задачи** — группировка по датам, прогресс, свайп вправо/влево для
  выполнения (подложка повторяет скругление карточки, без чёрных уголков),
  плавные счётчики без рывков, тап по карточке открывает календарь, долгое
  нажатие или «Подробнее» — экран задачи с Hero-анимацией.
- **Расписание** — Пн–Сб, раскрывающиеся дни, подсветка текущего дня, бейджи
  «сегодня» / «завтра» (после последнего урока статус переезжает на следующий
  учебный день), живая плашка «Первый урок в 08:00» / «Сейчас: Алгебра» /
  «Перемена до 08:50» / «Завтра: 7 уроков», карточка системы алиасов.
  Редактор по кнопке-карандашу: перетаскивание уроков, добавление и удаление,
  время и кабинет.
- **Кабинеты** — глобальный переключатель «Показывать кабинеты» плюс
  возможность очистить кабинет у отдельного урока.
- **Settings** — светлая / тёмная / системная тема, статистика,
  JSON-экспорт с предпросмотром и копированием.
- **Языковые режимы** — «Смешанный» (вкладки на английском, содержимое на
  русском) и полностью английский интерфейс.
- **Иконка New** — переключатель в настройках: стилус с линиями или обычный
  карандаш.
- **Зацикленная навигация** — между вкладками можно свайпать по кругу, а переход
  из New в Settings занимает один свайп, а не пролёт через все экраны.
- **Офлайн-хранилище** — Hive (IndexedDB в браузере, файлы на мобильном).
- **Журнал** — действия и ошибки приложения пишутся в локальный журнал
  (вкладка Settings → «Диагностика»): можно посмотреть, скопировать и очистить.
- **Резервная копия** — после каждого изменения задач в Hive кладётся снимок;
  в Settings есть кнопка «Восстановить».

## Быстрый старт

### 1. Установить Flutter

Нужен Flutter **3.27+** (проверено на 3.47.9 / Dart 3.13) и Android Studio для
эмулятора. Скачать Flutter: <https://docs.flutter.dev/get-started/install>.

Проверка:

```bash
flutter --version
flutter doctor
```

### 2. Платформы

Папки `android/` и `web/` уже есть в проекте. Если вы скопировали только `lib/`,
`pubspec.yaml` и `assets/`, создайте их один раз командой:

```bash
flutter create . --platforms=android,web --project-name school_diary
```

Команда добавит служебные папки платформ, не трогая готовый код в `lib/`.

### 3. Зависимости и запуск

```bash
flutter pub get
flutter run -d chrome        # браузер
flutter run                  # эмулятор/телефон, если подключён
```

Собрать APK без запуска на устройстве:

```bash
flutter build apk --release
# готовый файл: build/app/outputs/flutter-apk/app-release.apk
```

Релизная сборка подписывается ключом из `android/key.properties`
(файл и сам ключ `android/app/keystore/diary-release.p12` в git не попадают).
Если ключа нет, сборка автоматически откатывается на debug-подпись.

В веб-версии можно открыть конкретную вкладку: `?tab=tasks`, `?tab=schedule`
или `?tab=settings` — удобно для превью.

### 4. Тесты парсера

```bash
flutter test
```

В наборе 14 тестов парсера, три сквозных UI-теста (ввод домашки → задачи →
календарь → детали, языковые режимы, редактор расписания) и три теста
свайпов: влево = выполнено, вправо = вернуть, короткий свайп отменяется.

### Модель Task

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `String` | UUID v4, ключ в Hive |
| `subject` | `String` | канонический предмет |
| `description` | `String` | текст домашки без хэштегов |
| `deadline` | `DateTime` | дата сдачи, обычно 20:00 |
| `createdAt` | `DateTime` | когда создана |
| `isCompleted` | `bool` | выполнена ли |
| `completedAt` | `DateTime?` | когда закрыта |
| `metadata` | `Map<String,dynamic>` | задел под будущие модули |

Модель не импортирует Hive и UI — её легко перенести в единую БД.

### Коллекции Hive

| Box | Содержимое |
| --- | --- |
| `tasks` | задачи, ключ — UUID |
| `schedule` | уроки по дням недели (1–5) |
| `aliases` | канонический предмет → список синонимов |
| `settings` | тема, язык, показ кабинетов |
| `diary_backups` | последняя и предыдущая резервные копии задач |
| `diary_logs` | журнал действий и ошибок (последние 400 записей) |

При первом запуске расписание и алиасы заполняются демо-данными. Задачи — нет,
поэтому сразу видно Empty State.

## Логика парсера

### 1. Мульти-вброс

```text
#алгебра упр 15 #русский параграф 3
```

превращается в две задачи:

1. Алгебра — «упр 15»
2. Русский язык — «параграф 3»

Текст до первого хэштега прикрепляется к первой задаче. Если хэштегов нет,
создаётся одна задача с предметом «Разное».

### 2. Очистка описания

```text
#химия выучить таблицу
```

→ предмет «Химия», описание «выучить таблицу».

### 3. Алиасы

`#общество`, `#общага`, `#квобщество` → «Обществознание».

Работают и другие: `#физра`, `#литра`, `#инфа`, `#англ`, `#матем` и т.д.
Список хранится в Hive, его можно расширять без изменения парсера.

### 4. Дедлайны и выходные

- «сегодня», «завтра», «послезавтра»;
- «в пятницу», «на понедельник», «к среде»;
- `12.11`, `12.11.2026`, «12 ноября»;
- если дата не указана — следующий учебный день, 20:00;
- **пятница/суббота + понедельник → воскресенье, 20:00**;
- дедлайн, попавший на субботу, переносится на воскресенье.

Пример: в пятницу `#физика на понедельник параграф 5` получит дедлайн
**воскресенье, 20:00**.

## Экспорт JSON

Кнопка «Показать JSON» в настройках собирает:

```json
{
  "format": "school-diary.unified-db",
  "schemaVersion": 1,
  "app": "Дневник",
  "exportedAt": "2026-11-10T18:00:00.000Z",
  "modules": {
    "homework": {
      "tasks": [],
      "schedule": {},
      "subjectAliases": {}
    }
  },
  "reservedModules": ["notes", "contacts"]
}
```

Формат специально оставляет место для заметок и контактов PDB. JSON можно
скопировать в буфер и сохранить как файл.

## Инструкция для новичка

### 1. Android Studio

1. Скачайте Android Studio с <https://developer.android.com/studio>.
2. Запустите установщик, оставьте компоненты по умолчанию:
   Android SDK, Android SDK Platform-Tools, Android Virtual Device.
3. При первом запуске пройдите Setup Wizard и дайте скачать SDK.
4. Откройте **Settings → Languages & Frameworks → Android SDK** и убедитесь,
   что установлены:
   - Android SDK Platform (последняя стабильная, например API 35/36);
   - Android SDK Build-Tools;
   - Android Emulator;
   - Android SDK Command-line Tools.
5. Установите Flutter:
   - скачайте архив с `docs.flutter.dev/get-started/install`;
   - распакуйте, например, в `~/development/flutter`;
   - добавьте `~/development/flutter/bin` в `PATH`;
   - в Android Studio установите плагины **Flutter** и **Dart**
     (Settings → Plugins).
6. Проверьте:

```bash
flutter doctor
```

Если doctor ругается на лицензии: `flutter doctor --android-licenses`.

### 2. Виртуальный эмулятор (AVD)

1. Android Studio → **Device Manager** (иконка телефона) → **Create Device**.
2. Выберите телефон, например **Pixel 8** → Next.
3. Выберите образ системы (API 35, x86_64) → Download → Next → Finish.
4. Запустите эмулятор кнопкой ▶.
5. В терминале проекта:

```bash
flutter devices          # эмулятор должен появиться в списке
flutter run              # запуск на эмуляторе
```

Первый запуск Android-сборки может занять несколько минут (Gradle).

#### Вариант без Android Studio (только командная строка)

Android Studio не обязательна — достаточно JDK 17 и Android SDK:

```bash
# 1. JDK 17 (системный JDK 25 для Gradle 9 не подходит)
export JAVA_HOME="$HOME/.local/jdk17"
export PATH="$JAVA_HOME/bin:$PATH"

# 2. SDK и переменные окружения
export ANDROID_SDK_ROOT="$HOME/Android/Sdk"
export ANDROID_HOME="$ANDROID_SDK_ROOT"
export PATH="$ANDROID_SDK_ROOT/platform-tools:$ANDROID_SDK_ROOT/emulator:$PATH"

# 3. Пакеты SDK, которые нужны проекту
sdkmanager "platform-tools" "platforms;android-36" \
           "build-tools;36.0.0" "emulator" \
           "system-images;android-35;default;x86_64"

# 4. Указать SDK и JDK для Flutter
flutter config --android-sdk "$ANDROID_SDK_ROOT" --jdk-dir "$JAVA_HOME"

# 5. Виртуальное устройство
avdmanager create avd -n Diary_Phone \
  -k "system-images;android-35;default;x86_64" -d pixel_6

# 6. Запуск эмулятора
emulator -avd Diary_Phone -no-snapshot -no-boot-anim -no-audio \
         -memory 1536 -cores 2 -gpu swiftshader_indirect
```

Сборка и установка без запуска IDE:

```bash
flutter build apk --debug
adb install -r build/app/outputs/flutter-apk/app-debug.apk
adb shell monkey -p com.schooldiary.school_diary -c android.intent.category.LAUNCHER 1
```

> На слабых машинах (мало ОЗУ) эмулятор и Gradle одновременно могут не
> поместиться в память. Соберите APK, затем запустите эмулятор, и только
> после загрузки ставьте APK. В `android/gradle.properties` для этого уже
> уменьшены `org.gradle.jvmargs` и число воркеров.

### 3. Запуск в Chrome

```bash
flutter run -d chrome
```

Плюсы: быстрее собирается, не нужен эмулятор, удобно смотреть вёрстку.
Минусы: некоторые жесты и клавиатура отличаются от телефона. Hive в браузере
использует IndexedDB, данные сохраняются между перезапусками вкладки.

Если Chrome не найден: `flutter devices` покажет доступные устройства;
можно указать `-d web-server` и открыть выданный адрес вручную.

### 4. Hot Reload

1. Запустите приложение (`flutter run` или из Android Studio кнопкой ▶).
2. Измените код и сохраните файл.
3. В терминале нажмите:
   - **`r`** — Hot Reload: быстро применяет изменения, сохраняет состояние и
     текст в полях;
   - **`R`** — Hot Restart: перезапускает приложение с чистым состоянием;
   - **`q`** — выйти.
4. В VS Code можно включить автосохранение и `flutter run` будет делать reload
   при сохранении. В Android Studio кнопка с молнией ⚡ — Hot Reload,
   зелёный ▶ — перезапуск.

Если hot reload не подхватил изменения структуры (новые поля модели, схема
Hive), используйте **Hot Restart** (`R`).

## Возможные проблемы

| Проблема | Решение |
| --- | --- |
| `flutter: command not found` | добавьте `<flutter>/bin` в `PATH` и перезапустите терминал |
| Android-сборка падает на Gradle/JDK | `flutter doctor -v`, установите JDK из Android Studio, проверьте `flutter config --jdk-dir` |
| Кириллица в пути проекта | некоторые Gradle-задачи капризны к не-ASCII путям; при ошибке перенесите проект в путь вида `~/Projects/school_diary` |
| На web старое состояние | очистите данные сайта (IndexedDB) или сделайте Hot Restart |
| DatePicker на английском | проверьте, что в `MaterialApp` подключены `GlobalMaterialLocalizations` и locale `ru_RU` |
| `flutter create .` | выполняется один раз для генерации `android/` и `web/`; код в `lib/` не перезаписывается |
| Gradle падает с `OutOfMemoryError` | уменьшите `org.gradle.jvmargs` в `android/gradle.properties` (например, `-Xmx1536m`) и закройте лишние приложения |
| Эмулятор тормозит или не стартует | меньше RAM и ядер: `-memory 1536 -cores 2 -gpu swiftshader_indirect`, либо используйте реальный телефон по USB |
