# Hash — техническая логика приложения

**Версия документа:** 1.1.0
**Назначение:** описание фактической внутренней логики «Hash» (школьный трекер домашних заданий): разбор ввода, расчёт дедлайнов, жизненный цикл задачи, хранение и взаимодействие с интерфейсом.
**Границы документа:** только реализованное поведение. Всё, что ещё не реализовано, помечено явно — раздел 5.

---

## 0. Карта системы

Приложение разделено на четыре слоя. Каждый слой знает только о слое ниже, UI не работает с Hive напрямую.

```
UI (features/*)  →  AppState (ChangeNotifier)  →  Domain (parser, resolver)  →  Data (repositories → Hive)
```

| Слой | Файлы | Ответственность |
| --- | --- | --- |
| UI | `lib/features/**`, `lib/widgets/**` | Отрисовка, жесты, ввод, навигация |
| State | `lib/state/app_state.dart` | Единый источник истины в памяти, мутации, уведомления |
| Domain | `lib/domain/homework_parser.dart`, `school_calendar.dart`, `subject_resolver.dart`, `subject_aliases.dart` | Текст → задачи, тег → предмет, расчёт дедлайна, учебные дни и каникулы, генерация алиасов из расписания |
| Data | `lib/data/repositories/**`, `lib/data/models/**` | Персистентность (Hive), модели, сериализация |
| Services | `lib/services/**` | Импорт/экспорт расписания и синхронизация нативного виджета |

**Хранилища Hive (локально, без сети):**

| Box | Ключ | Значение |
| --- | --- | --- |
| `tasks` | `task.id` (UUID v4) | Map задачи |
| `schedule` | номер дня 1–7 | список уроков дня |
| `aliases` | канонический предмет | ручные алиасы (полностью заменяют сгенерированные) |
| `settings` | `themeMode`, `language`, `showRooms`, `newIconLines`, `saturdayOff`, `holidays` | строка/флаг/список периодов |
| `diary_backups` | `latest`, `previous` | снимок задач `{at, count, json}` |
| `diary_logs` | автоинкремент | строка журнала (макс. 400) |
| SharedPreferences `HomeWidgetPreferences` | `schedule_data` | JSON для нативного Android-виджета |

`SchoolCalendar` не хранится отдельно: он собирается на лету из расписания, `saturdayOff` и `holidays`, поэтому парсер и UI всегда видят актуальный календарь.

**Порядок запуска:** `Hive.initFlutter` → `AppLog.init` → инициализация 4 репозиториев параллельно → `AppState.load()` → `runApp`. Старт **zero-seed**: расписание и предметы при первом запуске пустые, дефолтные уроки и алиасы из кода не подставляются. Словарь предметов строится из сохранённого расписания.

## 1. Логика парсера

### 1.1 Конвейер разбора

```
ввод (String)
  └─ trim(); пусто → []
  └─ поиск всех хэштегов  RegExp(r'#([^\s#]+)', unicode)
       ├─ хэштегов нет → одна задача «Разное»
       └─ есть → по одному сегменту на каждый хэштег
            └─ tag  → _cleanTag() → resolver.resolve()  → предмет
            └─ слипшийся тег → resolver.splitGlued()    → предмет + хвост
            └─ body → _cleanDescription()               → описание
            └─ body → _deadlineFor()                    → дедлайн
```

Разбор выполняется на **каждое изменение текста** (для счётчика «Распределить · N» и подсказок) и повторно при отправке. Парсер без состояния, детерминирован при фиксированном `now`.

### 1.2 Разделение строки на задачи

Правило: **один хэштег = одна задача**.

1. Находятся все вхождения `#([^\s#]+)`.
2. Хэштег — это `#` и всё до ближайшего пробела или следующего `#`. Поэтому `#алгебра#физика` даёт два тега, даже без пробела.
3. Тело задачи — текст **после** её хэштега и **до** следующего хэштега.
4. Текст до первого хэштега («префикс») добавляется к телу **первой** задачи: `срочно #физика параграф 5` → описание `срочно параграф 5`.
5. Хэштеги вырезаются из описания; пробелы и переводы строк схлопываются в один пробел, края обрезаются.
6. Если после очистки тег пустой (`#!!!`) — сегмент пропускается.
7. Если после очистки description пустой — задача всё равно создаётся (`#алгебра#физика` → две задачи с пустым описанием).

### 1.3 Очистка тега и описания

| Функция | Что делает |
| --- | --- |
| `_cleanTag` | Убирает в начале и в конце всё, кроме `A–Z a–z А–Я а–я Ё ё 0–9 _ -`. Внутренние дефисы и подчёркивания сохраняются. |
| `_cleanDescription` | Удаляет все хэштеги, заменяет `[ \t]+` на пробел, склеивает переводы строк, обрезает края. |

Примеры очистки тега:

| Ввод | Тег после очистки | Предмет |
| --- | --- | --- |
| `#алгебра,` | `алгебра` | Алгебра |
| `#алгебра!` | `алгебра` | Алгебра |
| `#физ-ра` | `физ-ра` | Физкультура |
| `#общага` | `общага` | Обществознание |
| `#!` | — (пусто) | сегмент пропущен |

### 1.4 Сопоставление предмета

`SubjectResolver` нормализует строку: нижний регистр, `ё → е`, удаление **всех** символов, кроме `a–z а–я 0–9`. Затем ищет точное совпадение по словарю, где ключ — каноническое название, а значения — алиасы.

```
resolve("Физ-Ра") → normalize → "физра" → найден алиас → "Физкультура"
```

Если точного совпадения нет — выполняется «приведение к виду» (`_prettify`): `_`/`-` заменяются пробелом, каждое слово с заглавной буквы. Пустая строка → `Разное`.

**Словарь строится из расписания.** Зашитого списка предметов больше нет. `SubjectAliases.build()` берёт все уникальные названия уроков из Hive и для каждого генерирует префиксы от 3 символов: `Алгебра` → `алг`, `алге`, `алгеб`, `алгебр`; `Русский язык` → `рус`, `русск`, … Служебное слово `язык` пропускается, чтобы не давать алиас `язык`. Если префикс уже занят другим предметом, он не дублируется (`Физкультура` получает `физк` вместо `физ`, если `физ` уже у `Физики`).

**Ручные алиасы** (`aliases` в Hive, редактор в настройках) имеют приоритет: если для предмета задан хотя бы один ручной алиас, сгенерированный набор для него **полностью заменяется**. Пустой список — осознанное «только полное название». Сгенерированные префиксы не сохраняются: они пересобираются после каждого изменения расписания.

```
Алгебра        → [алг, алге, алгеб, алгебр]
Русский язык   → [рус, русск, русски, русский]
```

**Inline-автодополнение (`completionFor`)** работает прямо в поле ввода: нужен минимум 2 символа; нормализованный префикс сравнивается **только с каноническими названиями** предметов. Хвост достраивается до полного канонического имени: `ал` → `Алгебра` (призрачный хвост `гебра`), `общ` → `Обществознание`; короткие алиасы вроде `алгеб` не обрезают подсказку. Продолжение рисуется «призрачным» серым текстом **строго в позиции курсора** (`GhostTextController.buildTextSpan`), а не в конце строки, поэтому подсказка работает и в середине текста. Если справа от курсора ещё продолжается то же слово, ghost не показывается — иначе хвост задвоился бы.

Пробел после слова применяет дополнение и превращает **слово под курсором** в `#хэштег` (`HashtagAutocompleteFormatter`), даже если после него уже есть текст. Тег всегда строится из канонического имени: `физ` + пробел → `#физика`, `общага` + пробел → `#обществознание`; курсор встаёт после пробела. Тап по чипсу предмета вставляет готовый тег в позицию курсора.

**Тег для вставки (`tagFor`):** нижний регистр, `ё → е`, всё небуквенное/нецифровое → `_`, края очищаются. `Русский язык → #русский_язык`, пусто → `#разное`.

**Слипшийся тег (`splitGlued`)** разбирается, только если весь тег неизвестен, длина алиаса ≥ 4 и префикс разрешается в известный предмет: `#алгебраупр15` → предмет `Алгебра`, хвост `упр15`. Если тег уже известен (`#русский_язык`) — он не режется.

### 1.5 Исключения и краевые случаи

| Ситуация | Поведение |
| --- | --- |
| Опечатка, которой нет в словаре (`#алгебраа`) | Не исправляется. Предмет = «Алгебраа» (prettify). |
| Слипшийся тег и текст (`#алгебраупр15`) | Делится: предмет `Алгебра`, описание `упр15`. |
| Лишняя пунктуация в теге (`#алгебра,`) | Отбрасывается по краям тега. |
| Несколько хэштегов в строке | Отдельная задача на каждый. |
| Дата до первого хэштега | Попадает в тело первой задачи → применяется к ней. |
| Дата между задачами | Применяется к задаче, в чьём сегменте стоит. |
| Хэштег без текста | Создаётся задача с пустым описанием. |
| Нет хэштегов | Одна задача «Разное»; если текст пуст после очистки — ничего. |
| Только `#!` | Задач нет → UI показывает «Не получилось найти задачи». |
| Регистр и `ё` | Не важны (`#ФИЗИКА`, `#физёра` → нормализация). |

**Ограничение:** нечёткого поиска (Левенштейн/опечатки) нет. «Терпимость» — нормализация, словарь алиасов, префиксные подсказки и разбиение слипшегося тега по известному предмету.

## 2. Логика вычисления дедлайнов

### 2.1 Две сущности: день урока и дедлайн

| Термин | Смысл |
| --- | --- |
| `due` | День, к которому задана домашка (день урока). Внутренняя переменная. |
| `deadline` | Момент, который видит пользователь: **20:00 накануне `due`**. |

Итоговое правило:

```
deadline = 20:00 в день (due − 1)
если (due − 1) раньше сегодняшней даты → 20:00 сегодня
```

Время фиксировано: `defaultHour = 20` (параметр конструктора `HomeworkParser`). Секунды и минуты всегда `00`.

### 2.2 Приоритет источников даты

Проверка идёт строго сверху вниз, первое сработавшее правило выигрывает:

1. **Явная дата** — `12.11`, `12/11`, `12.11.2026`, `12 ноября`, `12 ноября 2026`.
2. **«послезавтра»**.
3. **«завтра»**.
4. **«сегодня»**.
5. **День недели** — `в понедельник`, `пн`, `среду`, `вс` и т.д.
6. **По умолчанию** — ближайший урок этого предмета по расписанию (см. 2.9); если предмета в расписании нет — ближайший учебный день **после** сегодняшнего (воскресенье и каникулы пропускаются), с правом переноса (см. 2.6).

Текст предварительно приводится к нижнему регистру и `ё → е`, затем режется на слова по всем не-буквам/цифрам. Поэтому пунктуация вокруг слов не мешает: `завтра,` = `завтра`.

### 2.3 Явные даты

- Числовой формат: `(\d{1,2})[./](\d{1,2})` + опциональный год `[./](\d{2,4})`.
- Текстовый формат: `(\d{1,2}) <месяц в родительном падеже>` + опциональный год из 4 цифр.
- Год из двух цифр → `20xx`.
- Если год не указан и дата уже прошла **по календарю**, берётся следующий год.
- Невалидная дата (`32.13`, `31 февраля`) игнорируется как явная — включается следующее правило.
- Приоритет: числовой формат проверяется раньше текстового.

### 2.4 Ключевые слова

Сравнение по началу слова: `завтра` ловит `завтра`, `завтрашний`; `сегодня` — `сегодня`, `сегодняшний`; `послезавтра` проверяется раньше `завтра`, чтобы не перехватить его.

### 2.5 День недели

Стемы: `понедельник/пн`, `вторник/вт`, `сред*/ср`, `четверг/чт`, `пятниц*/пт`, `суббот*/сб`, `воскресень*/вс`.

- Двухбуквенные формы совпадают только целиком (`вт` ≠ `вторник`).
- Более длинные — по префиксу (`среду`, `среды`, `среда` → среда).
- Если сегодня этот же день, но время **≥ 20:00**, берётся тот же день следующей недели.

### 2.6 Дата по умолчанию и перенос после 20:00

Если дата не указана, парсер ищет **первый подходящий урок этого предмета в ближайшие 28 дней** (см. 2.9). Отсчёт начинается с `today + 1`, а не с сегодняшнего дня: домашка, заданная в пятницу на предмет, который стоит в понедельник, не должна «сгорать» вечером пятницы.

```
start = завтра (today + 1)
для i = 0..27:
    candidate = start + i дней
    пропустить, если каникулы / воскресенье / отключённая суббота
    пропустить, если у предмета нет урока в этот день недели
    если включён сдвиг «через N уроков» и ещё не набрано N:
        запомнить и продолжить
    deadline = 20:00 накануне candidate
    если deadline уже прошёл:
        продолжить поиск
    вернуть due = candidate, deadline
```

Если за 28 дней подходящего урока нет (предмета нет в расписании или каникулы длиннее окна), работает запасное правило:

```
due = следующий учебный день после сегодня
deadline = 20:00 накануне due
пока deadline < текущего момента:
    due = следующий учебный день после due
    deadline = 20:00 накануне due
```

Из этого следуют три эффекта:

- Дедлайн **никогда не в прошлом** по времени для дат «по умолчанию».
- Если домашка добавлена после 20:00, она автоматически уходит на следующий учебный день.
- Воскресенье при выборе «следующего учебного дня» пропускается; суббота — учебный день, если не включён режим «суббота-выходной»; каникулы пропускаются.

### 2.7 Воскресенье и выходные

| Правило | Поведение |
| --- | --- |
| Дата по умолчанию | Воскресенье пропускается: суббота → понедельник. |
| Перенос после 20:00 | Тоже пропускает воскресенье. |
| Явно указанное воскресенье (`в воскресенье`) | Не запрещается: `due` = воскресенье, дедлайн = суббота, 20:00. |
| Дедлайн, попавший на воскресенье | Разрешён (это вечер перед понедельником). |
| Суббота | Учебный день, пока в настройках не включён «Суббота — выходной». |
| Каникулы | Периоды из настроек; уроки в эти дни пропускаются, явный день недели сдвигается вперёд. |
| Явная числовая дата на каникулах | Не сдвигается: пользователь указал конкретный день. |

Режимы «Каникулы/Выходные» задаются на экране расписания: переключатель субботы и список периодов с датами. Парсер получает их через `SchoolCalendar` при каждом разборе.

### 2.8 Примеры (опорная точка: четверг, 13.11.2025, 10:00)

Примеры ниже даны для расписания, где ближайший урок предмета совпадает с указанным `due` (иначе дата по умолчанию считается по разделу 2.9).

| Ввод | `due` | `deadline` | Комментарий |
| --- | --- | --- | --- |
| `#алгебра упр 15` | пт 14.11 | **чт 13.11, 20:00** | Вечер накануне урока |
| `#алгебра на завтра` | пт 14.11 | чт 13.11, 20:00 | «Завтра» = урок в пятницу |
| `#алгебра послезавтра` | сб 15.11 | пт 14.11, 20:00 | |
| `#история на понедельник` | пн 17.11 | **вс 16.11, 20:00** | Дедлайн в воскресенье — вечер перед уроком |
| `#алгебра на четверг` (10:00) | чт 13.11 | чт 13.11, 20:00 | Сегодня; вчерашний вечер не предлагается |
| `#алгебра на четверг` (21:00) | чт 20.11 | ср 19.11, 20:00 | День уже «закрыт» → следующая неделя |
| `#литература 14 ноября` | пт 14.11 | чт 13.11, 20:00 | Явная дата = день урока |
| `#литература 12 ноября` | чт 13.11 | чт 13.11, 20:00 | Прошлая дата прижата к сегодня |
| `#физика` (пт, 10:00) | сб 15.11 | пт 14.11, 20:00 | Суббота — учебный день |
| `#физика` (сб, 10:00) | пн 17.11 | вс 16.11, 20:00 | Воскресенье пропущено |
| `#физика` (сб, 21:00) | пн 17.11 | вс 16.11, 20:00 | Дедлайн ещё впереди |
| `#алгебра` (чт, 21:00) | сб 15.11 | пт 14.11, 20:00 | Вечер четверга уже прошёл |

### 2.9 Сопоставление предмета с расписанием

**Реализовано в `HomeworkParser._subjectDeadline` + `SchoolCalendar`:**

```
start = today + 1
для i = 0..27:
    candidate = start + i
    isSchoolDay(candidate) — не каникулы, не воскресенье,
                             не отключённая суббота
    hasLessonFor(subject, candidate.weekday) — урок предмета в этот день
    deadline = 20:00 накануне candidate
    если deadline > now → вернуть candidate
```

- Окно поиска — **28 календарных дней**, а не «до конца недели». Этого хватает на каникулы и переносы, но поиск не уходит в бесконечность.
- Предмет сопоставляется через `SubjectResolver`, поэтому `Общество` → `Обществознание`, `Труд` → `Технология`, `ОБЗР` → `ОБЖ`.
- «На следующий урок» = пропустить 0 найденных уроков, «через урок» = 1, «через N уроков» = N. Сдвиг применяется к подходящим урокам предмета, а не к календарным дням.
- Если предмета нет в расписании или все 28 дней заняты каникулами/выходными — работает запасное правило из 2.6.
- `saturdayOff` влияет и на парсер, и на экран расписания: суббота либо учебный день, либо помечается «Выходной» и исключается из расчётов.

**Пример:** четверг 13.11.2025, 10:00; история по расписанию только в понедельник. `#история глава 5` → `due` = понедельник 17.11, `deadline` = воскресенье 16.11, 20:00. Если каникулы длятся с 17.11 по 5.12, ближайший урок — 8.12, дедлайн — 7.12, 20:00.

**Следствие:** расписание стало источником дат по умолчанию. Явная дата, «завтра/послезавтра/сегодня» и день недели по-прежнему имеют приоритет и расписание не переопределяют.

### 2.10 Ручная правка дедлайна

Ручной пикер (`pickHomeworkDeadline`) работает иначе, чем парсер: выбранная дата **и есть дедлайн**, время принудительно `20:00`. То есть выбор «14 ноября» даёт `14.11, 20:00`, а не вечер накануне. Пикер: от `сегодня − 1 год` до `31.12` текущего года + 3.

## 3. Глобальная логика и Data Flow

### 3.1 Жизненный цикл задачи

```
[Текст в New]
     │ distribute()
     ▼
HomeworkParser.parse()
     │ ParsedHomework{subject, description, deadline, rawTag}
     ▼
Task.create()  ── id = UUID v4, createdAt = now, isCompleted = false
     │
     ├─ TaskRepository.saveAll()  → Hive box `tasks`
     ├─ AppState._tasks.addAll + _sortTasks + notifyListeners
     ├─ AppLog.info("Добавлено задач: N")
     └─ BackupRepository.save()   (фоново, unawaited)
     ▼
[UI: Tasks / карточка / детали]
     │
     ├─ toggleCompleted()  → copyWith(isCompleted, completedAt) → save → замена в списке → backup
     ├─ updateTask()       → save → замена в списке → backup        (смена дедлайна)
     └─ deleteTask()       → Hive.delete → удаление из списка → backup
```

Задача неизменяема: любое изменение — это `copyWith` и замена элемента списка по `id`.

### 3.2 Состояния задачи

Постоянное состояние в модели только одно — `isCompleted` (+ `completedAt`). Всё остальное вычисляется на лету.

| Отображение | Где | Правило |
| --- | --- | --- |
| Просрочено | заголовок группы, карточка, детали | `!isCompleted && deadline < now` |
| Сегодня / Завтра / Послезавтра | заголовок группы | разница календарных дат = 0 / 1 / 2 |
| День недели + дата | заголовок группы | разница > 2 дней |
| Выполнено | отдельная секция внизу | `isCompleted == true` |
| Прогресс `%` | карточка статистики | `completed / всего * 100`, округление |
| `beforeSchool` | плашка расписания | до начала первого урока |
| `inLesson` | плашка расписания | попадание в интервал урока |
| `onBreak` | плашка расписания | между уроками, до следующего |
| `tomorrow` / `nextDay` | плашка расписания | учебный день закончился |

Статусы не хранятся в Hive — при смене суток они пересчитываются из `deadline` и `DateTime.now()`.

### 3.3 Сортировка и группировка

**Сортировка `_tasks` (глобально):**
1. Активные раньше выполненных.
2. Активные — по `deadline` по возрастанию.
3. Выполненные — по `completedAt` (или `createdAt`) по убыванию.

**Экран Tasks:**
1. Активные группируются по **календарной дате** дедлайна (`dateOnly`).
2. Ключи групп сортируются по возрастанию.
3. Каждая группа получает заголовок из `groupTitleFor` и счётчик.
4. Группа с датой в прошлом помечается `isOverdue` (красный акцент).
5. Ниже — секция «Выполнено» со всеми выполненными.

### 3.4 Перемещение между днями

| Что | Перемещается ли |
| --- | --- |
| Задача после создания | Нет. Дедлайн фиксирован; меняется только подпись группы («Сегодня» → «Просрочено»). |
| Дедлайн при создании | Да, вычисляется по правилам раздела 2. |
| Дедлайн после 20:00 (без явной даты) | Да, при создании сразу ставится на следующий учебный день. |
| Дедлайн вручную | Да, пользователем через пикер (дата + 20:00). |
| Воскресенье | Не учебный день для расчётов; задача может иметь дедлайн в воскресенье. |
| Выполненная задача | Уходит в секцию «Выполнено», но дата дедлайна не меняется. |

Автоматического «перетаскивания» просроченных задач на сегодня нет: они остаются в своей дате с меткой «Просрочено».

### 3.5 Взаимодействие с интерфейсом

**New (быстрый ввод):**

| Действие | Результат |
| --- | --- |
| Ввод текста | На каждый символ: inline-дополнение серым текстом до канонического названия (от 2 символов) и пересчёт количества задач |
| Пробел после известного слова | Слово применяется и превращается в канонический `#хэштег` |
| Тап по чипсу предмета | Вставка готового `#тег` в позицию курсора |
| «Распределить · N» | `AppState.distribute`: создание N задач, очистка поля, мягкое зелёное свечение кнопки (без снекбара) |
| Пустой ввод | Снекбар «Сначала напиши домашку…» |
| Ничего не распознано | Снекбар «Не получилось найти задачи…» |
| Клавиатура | Высота нижней панели анимируется вместе с `viewInsets`; при скрытии клавиатуры контент и кнопка не прыгают |

**Tasks:**

| Жест | Результат |
| --- | --- |
| Свайп влево (от правого края) | Зелёная подложка «Выполнено» / «Вернуть»; переключает статус |
| Свайп вправо (от левого края) | Красная подложка «Удалить» с корзиной; удаляет задачу и показывает снекбар |
| Короткий свайп | Возврат на место (порог: 32 % ширины или 650 px/s) |
| Тап по карточке | Открывает **пикер даты** (быстрая смена дедлайна) |
| Долгое нажатие / кнопка «Подробнее» | Экран задачи; у кнопки увеличенная зона нажатия (44 px) |
| Кнопка-кружок | Переключение выполнения: карточка плавно сворачивается (240 мс) и появляется в новой секции |
| В деталях: дата / выполнено | `updateTask` / `toggleCompleted`; удаление — отдельной красной кнопкой внизу экрана |

**Навигация:** 4 вкладки в бесконечном `PageView` (`initialPage: 4000`) с `NeverScrollableScrollPhysics`. Смена — только тапом по навбару. Тап сразу меняет `_selectedIndex` и запускает `animateToPage`; на время анимации поднят флаг `_isAnimatingByTap`, поэтому `onPageChanged` не дёргает капсулу промежуточными страницами. Переход между крайними вкладками (Settings ↔ New) занимает **одну страницу** за счёт пересчёта дельты по кругу. Выбранная вкладка подсвечивается «ездящей» капсулой (`AnimatedPositioned`), цвет иконок и подписей плавно интерполируется. Корневой `Scaffold` использует `extendBody: true`: контент виден под прозрачной обёрткой навбара, а списки оставляют отступ `PillNavBar.contentInset`.

**Schedule:**

| Элемент | Поведение |
| --- | --- |
| Дата дня | `weekStart = понедельник текущей недели`; дата дня = `weekStart + (day − 1)` |
| Карточка дня | Пн–Сб раскрываются; сегодня/завтра раскрыты сразу; при `saturdayOff` суббота скрывается как выходной |
| Воскресенье | `Выходной`, без раскрытия и без шеврона |
| Бейджи | «сегодня» — пока не закончился последний урок (или до 14:00, если уроков нет); «завтра» — только если следующий учебный день наступает буквально завтра |
| Плашка «Сейчас» | Во время урока два чипса: «Сейчас: Русский язык · 08:00–08:40» и «Далее: Литература (08:55–09:35)» |
| Плашка «Перемена» | «Перемена до 08:55 · Далее: Литература» |
| Каникулы | Если сегодня праздничный день, рядом с плашкой показывается чип «Каникулы» |
| Полночь | Таймер `_WeekTicker` перерисовывает вкладку: даты и бейджи не застывают |
| Редактор (иконка карандаша) | Пн–Сб, добавление/правка/удаление/перетаскивание уроков; сохранение после каждого изменения |
| Поля урока | Предмет (обязателен), кабинет, начало и конец через барабанный пикер времени; конец автоматически = начало + 40 минут |
| Каникулы/Выходные | Переключатель «Суббота — выходной» и список периодов каникул с датами; периоды можно удалять |

### 3.7 Ошибки и устойчивость

- Ошибки Flutter и непойманные исключения пишутся в `AppLog` (`FlutterError.onError`, `PlatformDispatcher.onError`).
- Повреждённая запись задачи при чтении пропускается, остальные загружаются.
- Сбой записи резервной копии логируется и не роняет приложение.
- Все операции записи идут через `await` к репозиторию, затем обновляется память и вызывается `notifyListeners`.
- Открытие журнала при сбое Hive не блокирует запуск.

### 3.8 Формат журнала (текущий)

```
12.11.2026 16:14:05  INFO  Добавлено задач: 2
    #0  ...
```

`<ДД.ММ.ГГГГ> <ЧЧ:ММ:СС>  <LEVEL>  <текст>`, стек — до 12 строк с отступом.

### 3.9 Нативный Android-виджет

Виджет — отдельный нативный слой, Flutter-код в нём не выполняется.

```
AppState (расписание/звонки/showRooms/saturdayOff/тема)
   └─ HomeWidgetService.sync()
        ├─ HomeWidget.saveWidgetData('schedule_data', json)
        └─ HomeWidget.updateWidget(androidName: 'ScheduleWidgetProvider')

ScheduleWidgetProvider (Kotlin)
   ├─ читает SharedPreferences HomeWidgetPreferences['schedule_data']
   ├─ рисует RemoteViews на 8 фиксированных строк
   └─ ставит AlarmManager на границы уроков и полночь
```

| Часть | Поведение |
| --- | --- |
| Формат данных | `{version, showRooms, saturdayOff, dark, english, days: {'1'..'7': [Lesson]}}` |
| Заголовок | «Сегодня · Понедельник»; при переполнении — `+N` скрытых строк |
| Уроки | Уроки текущего дня; прошедшие — прозрачность 0.45, текущий — акцентная капсула, следующий — тонкая рамка |
| Перемена | Узкая полоска «Перемена · до HH:MM», только если перемена идёт прямо сейчас |
| Кабинеты | Добавляются к названию только при `showRooms: true` |
| Выходной | Воскресенье и отключённая суббота — «Выходной»; пустой день — «Сегодня уроков нет» |
| Размер | 4×2 по умолчанию, `resizeMode="horizontal|vertical"`; число строк зависит от высоты |
| Обновление | `AlarmManager` на начало/конец каждого урока и на полночь; неточный режим, если нет разрешения на exact alarms |
| Тема | Цвета light/dark передаются из Flutter, поэтому виджет совпадает с приложением |
| Язык | Подписи переключаются флагом `english` |

## 4. Инварианты (короткий чек-лист)

1. Один хэштег = одна задача.
2. Нет хэштегов = задача «Разное».
3. Тег нормализуется (регистр, `ё`, пунктуация, дефисы) до сравнения со словарём; слипшийся тег делится по известному предмету.
4. Дедлайн всегда `20:00`; в модели хранится полная дата-время.
5. Словарь предметов строится из расписания; сгенерированные префиксы не сохраняются, ручные алиасы заменяют их полностью.
6. Дедлайн по умолчанию — вечер накануне первого подходящего урока предмета в ближайшие 28 дней; если уроков нет — накануне ближайшего учебного дня.
7. Дедлайн «по умолчанию» не может быть в прошлом по времени.
8. Явная дата = день урока; её дедлайн — вечер накануне (но не раньше сегодняшней даты).
9. Воскресенье, каникулы и отключённая суббота — не учебные дни для расчётов.
10. Задача не меняет дедлайн сама после создания.
11. Все данные локальны; сеть не используется.
12. Снимок задач сохраняется после каждой мутации (последние две версии).
13. UI не обращается к Hive напрямую — только через `AppState`.
13. Календарь (`SchoolCalendar`) собирается на лету: изменения расписания и каникул сразу влияют на парсер.
14. Смена вкладок — только тапом, без прокрутки промежуточных экранов.
15. Свайп влево переключает выполнение, свайп вправо удаляет задачу.

## 5. Известные ограничения и точки расширения

| Область | Ограничение | Направление доработки |
| --- | --- | --- |
| Парсер | Нет исправления опечаток | Нечёткое сравнение (расстояние Левенштейна) по словарю и алиасам |
| Парсер | Слипшийся тег делится только по известному предмету | Больше эвристик для сложных случаев |
| Дедлайн | Время 20:00 зашито | Настройка времени дедлайна (и/или отдельное время для каждого предмета) |
| Дедлайн | Явная прошлая дата прижимается к сегодня | Решить: запрещать, переносить вперёд или оставлять просроченной |
| Каникулы | Периоды задаются вручную | Импорт учебного календаря / автоопределение |
| Расписание | Уроки без привязки к звонкам школы | Профили звонков и разные расписания по неделям |
| Бэкап | Копируются только задачи | Включать расписание, алиасы и настройки либо делать полный снимок |
| Экспорт | Отсутствует (удалён из UI) | Файл/шеринг и импорт |
